# TPM local integration rules

This reference adapts TPM to the selected task-specific, local-only toolkit. It overrides native plugin command syntax, external-reference refresh exceptions and any instruction implying that a draft has already been sent, approved or executed.

## Artifact authority

- Use local supplied specs, PRDs, glossary/ADRs, plans, commits, exported issue data and user answers. No network, RAG, connectors or runtime book retrieval.
- Use docs/tpm/ unless the user names another local destination. Preserve approved baselines; when asked only to review, produce findings or proposed revisions.
- Resolve factual questions from available local evidence. User-owned decisions and unknown commitments remain open. Proposed owners are not accepted assignments.
- Label assumptions and open questions. Missing named owners may use a proposed role or unassigned. Missing dates use an explicit needed-by trigger or TBD, never an invented commitment.
- A stage-local artifact includes its source IDs, version/as-of date, unknowns and completion check. Planned deployment/launch tasks do not authorize deployment or launch.
- Communication plans describe cadence and recipients only. Do not send messages, create meetings/reminders, enroll automations, change permissions or claim pre-communication occurred.
- Run the selected stage only. The router may select multiple stages when requested, but order is dictated by fields actually read, not a mandatory pipeline.
- An existing artifact is reusable only if its scope, source versions, assumptions and as-of evidence remain applicable. File existence alone does not mean current.

## Shared references

The preserved program/project test and closing clarity checklist are under references/tpm-common/ for stage skills. The router has the same files directly under references/. Resolve any upstream sibling TPM reference to these bundled equivalents, not to a guessed host plugin path.

## Scheduling safeguards

- Distinguish ideal effort, buffered effort, elapsed duration, available capacity and calendar dates, with explicit units.
- Treat source buffer percentages as an illustrative planning convention, not measured facts or universal recommendations.
- Do not count the same meetings, on-call or leave twice: represent known unavailability explicitly or through capacity/overhead once and state the model.
- Do not divide effort by headcount unless the work is actually separable, resources are available and crash counts permit it. Shared resources cannot be assigned simultaneously at full capacity.
- Record predecessor type and lag: fs, ss, ff and sf are scheduling constraints. Name the actual data/authority handoff before translating an execution dependency into a schedule constraint.
- A longest dependency chain without resource/calendar analysis is not a validated delivery forecast. Distinguish dependency critical sequence from resource-constrained schedule.
- When no team, estimates or availability are supplied, produce the complete structural plan but leave numerical forecasts unknown.
- For risk ranking, preserve the source's ordinal P+I score, not P×I; do not call ordinal score a probability or expected-loss estimate.
- Status cannot claim green from missing or stale actuals. Unknown impact is provisional/uncertain; explain evidence limits and the next decision/check date or trigger.
