# TPM risk

Produce the risk log: what might happen, how likely, how bad, what we will
do about it in what order, how we will see it coming, and who owns it.

Offline: use only `references/` and `assets/` here and in `../tpm/`. No
rag-mcp calls, no URLs.

## Inputs

- The plan (`docs/tpm/wbs.md`) — the Gantt is the first place risks show:
  parallel work that assumes nothing fails, single tasks everything waits
  on, tasks touching fragile services.
- The charter and requirements.
- Any existing risk list, issue list, or "risks and considerations" section
  in the repo's plan documents.
- Stakeholder and team input, if the user can supply it (a kickoff working
  session is the best source; ask whether one has happened).

## Produce

1. Read `029.md`.
2. Copy `026.md` to `docs/tpm/risk-register.md` (or the
   user's path). For every entry:
   - state a *risk* (might happen), not an issue (is happening) — issues go
     to the status report's issue table;
   - name the task, dependency, or phase it threatens and what it blocks
     downstream;
   - score probability and impact separately (L/M/H = 1/2/3); score is the
     sum;
   - give a signal that would show it materialising ahead of time;
   - list every applicable strategy in the order they would be tried,
     labelled avoid / mitigate / transfer / accept, and mark which one is
     current;
   - say what the plan changed as a result (new task, buffer, moved date) —
     and make that change in `wbs.md` if it exists;
   - assign an owner and the level (project / program / both).
   Break coarse risks into outline-numbered sub-risks when their parts have
   different probability or impact.
3. Sweep the software life-cycle table in `029.md`
   (requirements, design, implementation, testing, evaluation, cross-phase)
   and add anything that applies that the inputs missed. For a program, add
   the cross-project risks: shared subsystems, interoperability testing,
   contract drift.
4. Add deep-dive tasks (spike, PoC, training) for any risk not understood
   well enough to score, and list them in the Deep-dive table.
5. Run the "Clarity questions for this artifact" at the end of
   `029.md`. Unanswered questions go in the Open questions
   table.

## Report

Path of the log, the count of risks by score band, the score-5–6 risks in
one line each with owner and current strategy, and open questions with
owners.
