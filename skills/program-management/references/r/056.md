# TPM

## Scope

Read `060.md` and `062.md` at task start. Work only from local files and supplied context. Produce drafts, not external communications, automatic implementation or persistent modes.

## Workflow

1. Read existing local program artifacts and identify the requested stage and goal. Ask only for information the files cannot answer.
2. Apply the bundled program-versus-project test and state the classification and rationale. Do not treat multiple features alone as a program.
3. If a stage was named, select only that stage. Otherwise identify missing or stale artifacts and propose the smallest applicable stage set.
4. Invoke the declared stage skill through the host, or read its installed sibling hub. Reuse outputs only when their actual source evidence is current.
5. Follow real artifact dependencies. Charter informs a delivery plan; risk and stakeholder analysis may begin earlier when their inputs exist. Status reads the selected authoritative plan, risks, actuals and communication inputs.
6. Run the shared closing clarity check on produced artifacts. Repair only the owning stage, with the existing two-round cap; keep unresolved items visible.
7. Report local artifact paths, program/project classification and consolidated open questions. No external publication, implementation or persistent orchestration.

## Default output

Selected-stage artifact index, classification rationale, freshness/coverage limits and open questions with known or proposed owners.

## Failure boundary

Keep missing estimates, capacity, names, approvals and dates as explicit unknowns. Repair only the failing artifact within the shared bounds, then escalate unresolved decisions. A populated template is not evidence that work, notification, approval or delivery occurred.
